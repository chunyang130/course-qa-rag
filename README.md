# 課程問答 RAG：檢索＋引用驗證，資料沒有就說沒有

> A retrieval-augmented Q&A bot for course information: BM25 retrieval over a small knowledge base, answers generated by Claude with forced citations, and program-side checks that every quote and number actually comes from the retrieved text. Includes an evaluation set with unanswerable questions. Python standard library only.

學員常問的問題（價格、退費、上課方式、獎學金）都寫在補習班的規章裡，但顧問不一定記得最新規定。直接問一般 AI 聊天，它會用「常識」回答，可能跟公司規定不同。
這個專案做的是 RAG：**先從公司文件找出相關段落，再讓 Claude 只根據這些段落回答，並由程式檢查引用是否屬實**。

只用 Python 標準函式庫（3.10 以上），不需安裝任何套件。知識庫是虛構的「範例美語中心」資料。

## 流程

1. **切段**：知識庫每份文件依小標切成段落，每段有編號（例：`refund#2`），共 26 段
2. **檢索**：先用同義詞表把學員的說法換成文件用語，再用 BM25 演算法找出最相關的前 4 段。中文以兩字一組切詞，不需要另外的分詞套件或向量資料庫
3. **生成**：只把這 4 段交給 Claude，用 tool use 強制回傳「能否回答、答案、引用」；引用的段落編號只能從這 4 段中選
4. **驗證**：由程式檢查
   - 引用的原文必須在段落裡一字不差
   - 答案裡的每個數字（金額、比例、天數）都必須出現在引用的段落中
   - 不合格就把錯誤回饋給模型重試一次
5. **拒答**：完全檢索不到相關段落時，直接回答「資料中找不到」，不呼叫 API；檢索到但內容不足時，由模型判斷並拒答

## 評估

`eval/questions.json` 有 17 題：14 題知識庫有答案，3 題沒有（日文課、老師證照、停車位），用來測試會不會亂答。

| 指標 | 意義 |
| --- | --- |
| 檢索命中率 | 正確段落有沒有出現在前 4 名 |
| 應答題答對 | 有回答、答案含關鍵資訊、引用通過驗證 |
| 拒答題正確拒答 | 資料沒有的問題，有沒有回答「找不到」 |
| 觸發重試 | 第一次回答沒通過程式驗證的題數 |

### 實際執行結果（Claude API，`claude-haiku-5-5`）

| 版本 | 檢索命中率 | 應答題答對 | 拒答題正確拒答 | 觸發重試 | 改了什麼 |
| --- | --- | --- | --- | --- | --- |
| v1 | 13/14 | 13/14 | 3/3 | 0 題 | — |
| v2 | **14/14** | **14/14** | **3/3** | 0 題 | 加入同義詞擴充 |

17 題的用量約為輸入 18,700、輸出 3,100 token。原始結果保留在 `eval/real_runs/`。

**v1 唯一答錯的是 q14「錯過一堂課怎麼補？」，問題出在檢索，不在模型**：資料寫的是「缺課可預約錄影補課」，關鍵字檢索認不出「錯過」和「缺課」是同義詞，正確段落沒被找出來，模型只能拒答。
v2 在檢索前加了同義詞表（例如 錯過→缺課、暫停→保留學籍），q14 的正確段落排到第 1 名，其他 13 題的命中結果沒有變差，3 題拒答題的檢索結果也完全相同。

**其他觀察**
- **不自行假設**：q02「開課後兩週想退費」，模型回答「資料未提供全期天數，無法確認是否仍在三分之一內，建議請顧問確認」，沒有自己假設是哪一門課
- **內容不足就拒答**：q17「分校有停車位嗎」有檢索到分校段落，但模型判斷內容不足，沒有用常識回答
- **說明資料範圍**：q14 回答補課方式後，補充「資料中沒有提到其他補課方式的細節」
- **驗證機制**：兩輪真實執行都沒有觸發重試；重試流程在示範模式中測試（`eval/mock_responses.json` 的 q01 故意寫錯金額，數字檢查擋下後重試改正）

**限制**：同義詞表是看到 q14 答錯後才加的，14/14 有針對這組題目修正的成分。要確認改進是否普遍有效，下一步應該用一組沒看過的新題目再評估一次。

## HTTP API：讓其他系統直接使用

`api.py` 把問答包成 HTTP 服務，每次問答都記錄到 SQLite，再用 SQL 分析使用狀況。只用 Python 內建的 `http.server` 與 `sqlite3`。

```bash
python api.py --mock eval/mock_responses.json     # 免費示範
python api.py                                     # 實際呼叫 Claude（需 ANTHROPIC_API_KEY）
```

| 端點 | 用途 |
| --- | --- |
| `GET /` | 問答網頁 |
| `GET /health` | 健康檢查 |
| `GET /examples` | 網頁上的範例問題 |
| `GET /search?q=退費&k=4` | 只做檢索，回傳相關段落（不呼叫模型、不花錢） |
| `POST /ask` | 送出 `{"question": "..."}`，回傳答案、引用段落、驗證結果與耗時 |
| `GET /stats` | 用 SQL 統計問答紀錄 |

```powershell
# Windows PowerShell 範例
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/ask -ContentType "application/json; charset=utf-8" `
  -Body ([System.Text.Encoding]::UTF8.GetBytes('{"question": "多益衝刺班一期多少錢？"}'))
```

回應：

```json
{
  "answerable": true,
  "answer": "多益衝刺班每期 NT$18,000，每期 12 週。",
  "citations": [{"chunk_id": "pricing#1", "quote": "多益衝刺班：每期 NT$18,000"}, ...],
  "retrieved": [{"chunk_id": "pricing#1", "score": 8.5}, ...],
  "validation_errors": [],
  "retried": true,
  "latency_ms": 3
}
```

**`/stats` 回答營運上的問題**（SQL 寫在 `api.py` 的 `STATS_SQL`）：

- 總覽：題數、拒答率、觸發重試、驗證未通過、平均耗時、token 用量
- 最常被問的問題：哪些問題該做成常見問題頁
- 被拒答的問題：**知識庫可能缺資料**，該補哪些文件

**輸入檢查**：缺少問題、問題超過 300 字、不是 JSON 都回 400；`/ask` 用 GET 回 405；不存在的路徑回 404；模型服務錯誤回 502。

`test_api.py` 以示範模式實際啟動伺服器、送出 HTTP 請求，檢查回應、錯誤碼、資料庫紀錄、網頁與範例題，並模擬容器的啟動方式（環境變數設定、沒有金鑰時的示範模式、每日上限），共 20 項。

## 容器化與雲端部署（Docker＋Google Cloud Run）

API 可以直接包成容器部署到雲端，得到公開的 HTTPS 網址：

```bash
docker build -t course-qa-rag .
docker run -p 8080:8080 course-qa-rag                                   # 沒有金鑰 → 示範模式
docker run -p 8080:8080 -e ANTHROPIC_API_KEY=... course-qa-rag          # 實際呼叫 Claude
```

- **設定都用環境變數**（`PORT`、`DB_PATH`、`ASK_DAILY_LIMIT`），同一個映像檔在本機、CI、雲端都能跑
- **金鑰放 Secret Manager**，不進程式碼、映像檔或 GitHub
- **費用控制**：最多 1 台、閒置縮到 0 台；`/ask` 每天上限 50 題，超過回 429，`/search` 不受影響
- **自動測試**：GitHub Actions 每次推送都會建置映像檔、啟動容器、實際送出請求（含每日上限）

完整步驟（全部在瀏覽器的 Cloud Shell 完成）：[docs/deploy-cloud-run.md](docs/deploy-cloud-run.md)

## 知識庫更新管線：資料檢查 → 評估閘門 → 自動部署

知識庫是 AI 回答的依據，**資料一改，答案就跟著變**。所以資料更新也要像程式一樣先測試、通過才上線。

**1. 業務只維護表格**：價目表放在 `sources/pricing.csv`（課程、價格、計價方式、備註），可以直接用 Excel 編輯。
程式載入知識庫時由 CSV 產生價目表文件（`kb_sources.py`），表格就是唯一的資料來源，不會發生「改了表格、忘了改文件」。

**2. 推送到 GitHub 後自動檢查**（`pipeline.py`，不呼叫 AI、不花錢）：

| 檢查 | 擋下的情況 |
| --- | --- |
| 資料檢查 | 欄位被改名、價格不是數字或超出合理範圍（例：36000 打成 3600）、課程重複、計價方式不是「每期／全年」 |
| 文件檢查 | 缺標題、空段落、段落超過 500 字（太長會降低檢索準確度） |
| 和上一版比較 | 列出價格變動與新增／修改／刪除的段落；**價格變動超過 30% 會擋下**，確認無誤要在提交說明寫「確認價格」 |
| 評估閘門 | 評估題的預期答案已不在資料裡（例：多益改價、評估題沒跟著改）；檢索命中率低於門檻 |

檢查報告會顯示在 GitHub Actions 該次執行的摘要頁，例如改了多益價格但沒更新評估題時：

```
## ❌ 未通過：不可部署，請依下方說明修正
### 3. 和上一版比較
- 內容有修改的段落：`pricing#1`
### 4. 評估閘門
- ❌ q01「多益衝刺班一期多少錢？」的預期答案（18,000／18000）已不在 pricing#1；資料改了，評估題與示範回覆要同步更新
```

**3. 全部通過才自動部署**：單元測試、知識庫評估閘門、容器測試三項都通過，才會建置映像檔並部署到 Cloud Run，部署後再自動檢查網址是否正常。
登入 Google Cloud 用 Workload Identity Federation，**GitHub 上不存放任何 Google 金鑰**；部署帳戶只有部署需要的最小權限。設定方式見 [docs/deploy-cloud-run.md](docs/deploy-cloud-run.md) 第 5 步。

```bash
python pipeline.py check                 # 檢查目前的資料
python pipeline.py preview               # 看由 CSV 產生的價目表文件
python test_pipeline.py                  # 模擬 9 種改資料的情況，確認該擋的有擋、該放的有放
```

## 為什麼用 BM25，不用向量檢索

知識庫只有 26 段，而且學員問題多半會用到文件裡的詞（多益、退費、獎學金），關鍵字檢索就夠用，也不需要額外的服務或套件，結果可以逐段解釋。
它的弱點是同義詞，例如 q14 的「錯過」和「缺課」。目前用人工維護的同義詞表補足；資料量變大、同義詞維護不完時，下一步是改用向量檢索（embedding），或與 BM25 混合使用。

## 學到的事

- RAG 的重點不只是「把資料給 AI」，而是**檢索得準**和**確認 AI 真的照資料回答**，兩邊都要能量測
- 評估題組一定要放「資料裡沒有答案」的題目，才知道 AI 會不會亂答
- 數字最容易出錯，也最容易檢查：答案裡的每個數字都必須能在引用段落中找到
- 檢索不到時直接拒答、不呼叫 API，既省成本，也避免模型憑空回答
- 答錯時要先分清楚是**檢索**沒找到，還是**模型**沒答好，修正的地方完全不同
